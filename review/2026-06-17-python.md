## Findings

### 1. **HIGH** — `page()` logs full stored HTML at INFO level  
**Location:** `app.py:501`  
**Issue:**  
```python
app.logger.info(
    f"page_id {page_id} Meta redirect found. Source:{row['html']}: Redirect:{meta_refresh_url}"
)
```  
`row['html']` is the stored page HTML — potentially megabytes per request. Logged at INFO means it appears in gunicorn logs by default, creating verbose output and leaking scraped content.  
**Fix:** Remove `Source:{row['html']}` from the log line; URL + redirect target is sufficient.

---

### 2. **MEDIUM** — `remove_nav_content` is called twice per page  
**Location:** `crawl.py:699` (worker) and `crawl.py:251` (inside `html_to_text_and_links`)  
**Issue:**  
`worker` calls `fr.html = remove_nav_content(fr.html)` and then passes the result into `html_to_text_and_links`, which immediately calls `remove_nav_content` again on the same HTML. The side-effect is that the HTML stored in `pages.html` is the nav-stripped version, not the original — making `/page/<id>` cached view show nav-less HTML. Whether this is intentional is unclear, but the double parse is wasteful and the stored HTML fidelity is reduced silently.  
**Fix:** Remove the inner `remove_nav_content` call from `html_to_text_and_links` (nav is already gone when called from `worker`), or keep the call only inside `html_to_text_and_links` and revert the mutation in `worker`.

---

### 3. **MEDIUM** — `asyncio.get_event_loop()` is deprecated in Python 3.10+  
**Location:** `crawl.py:506`, `crawl.py:732`, `crawl.py:748`  
**Issue:**  
```python
now = asyncio.get_event_loop().time()
```  
`asyncio.get_event_loop()` emits `DeprecationWarning` in Python 3.10+ when called from a coroutine (should use `asyncio.get_running_loop()`). The project targets Python ≥ 3.12 and the Docker image uses 3.14; this will eventually become an error.  
**Fix:** Replace all three occurrences with `asyncio.get_running_loop().time()`.

---

### 4. **LOW** — `_search_pages_threaded` opens SQLite without WAL PRAGMA  
**Location:** `app.py:393`  
**Issue:**  
```python
conn = sqlite3.connect(DB_PATH)
```  
This connection is used in a `ThreadPoolExecutor` for read queries. `get_db()` sets `PRAGMA journal_mode = WAL` and `PRAGMA foreign_keys = ON`; the thread-pool connection does neither. WAL mode is persistent per-database, so reads will still work, but omitting it is inconsistent and can cause `SQLITE_BUSY` under heavy concurrent write+read load if the journal mode has not yet been set.  
**Fix:** Add the same two PRAGMAs used in `get_db()` immediately after `sqlite3.connect()` in `_search_pages_threaded`.

---

### 5. **LOW** — `ResourceWarning: unclosed database` in test suite  
**Location:** `tests/test_page_ranking.py` (rank_results helper), `tests/test_app.py`  
**Issue:**  
Running tests with warnings enabled shows:  
```
ResourceWarning: unclosed database in <sqlite3.Connection object>
```  
The `rank_results` helper in `test_page_ranking.py` and several `SearchPagesTests` methods open `sqlite3.Connection` objects inside `with tempfile.NamedTemporaryFile()` blocks but don't close the connection before the `NamedTemporaryFile` exits. On macOS (where `NamedTemporaryFile` uses a real file path) this is benign; on Windows it causes test failures.  
**Fix:** Use `try/finally conn.close()` or a `with contextlib.closing(conn)` block in affected helpers.

---

### 6. **LOW** — `extract_meta_refresh` regex fails when `content=` appears before `http-equiv=`  
**Location:** `app.py:109`  
**Issue:**  
The regex `<meta[^>]+http-equiv=...content=...>` requires `http-equiv` to precede `content` in attribute order. HTML does not guarantee attribute order; many real-world pages write `<meta content="0;url=..." http-equiv="refresh">`.  
**Fix:** Use two separate lookaheads (or BeautifulSoup) instead of a positional regex. A minimal fix: add a second regex pattern with swapped attribute order and try both.

---

### 7. **INFO** — `nice_score` epsilon branch is unreachable in practice  
**Location:** `app.py:298`  
```python
score = round(-10.0 * bmscore, 7)
return 0.0000001 if bmscore < 0 and score == 0.0 else float(score)
```  
The condition `bmscore < 0 and score == 0.0` can only be true when `|bmscore| < 5e-9`. Real BM25 scores are never that close to zero. The branch exists to prevent rank collapsing in a test but is impossible to trigger through normal search. The comment "Codex changed" hints this was auto-generated rather than deliberately designed.  
**Fix:** Add a comment explaining the intent or simplify to `return float(score)` if the epsilon is genuinely unreachable.
