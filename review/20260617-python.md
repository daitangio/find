## Findings

### 1. `_search_pages_threaded` opens SQLite without WAL/foreign-key PRAGMAs
**Severity: HIGH**  
**Location:** `app.py`, `_search_pages_threaded()`

Every threaded search opens a raw `sqlite3.connect(DB_PATH)` with no PRAGMAs. `get_db()` sets `journal_mode=WAL` and `foreign_keys=ON`. Without WAL, threaded readers can block when the crawler is writing, causing slow or failed searches under load.

**Fix:** Apply the same two PRAGMAs as `get_db()`:
```python
conn = sqlite3.connect(DB_PATH)
conn.row_factory = sqlite3.Row
conn.execute("PRAGMA journal_mode = WAL;")
conn.execute("PRAGMA foreign_keys = ON;")
```

### 2. Unclosed SQLite connections in tests (and in `ensure_database_present`)
**Severity: MEDIUM**  
**Location:** `utils.py`, `ensure_database_present()`; also test helpers confirmed by `ResourceWarning`

`ensure_database_present` opens two `sqlite3.connect` calls without `try/finally`. If `fts5_available` raises, the connection leaks. The `ResourceWarning: unclosed database` printed during the test run traces back to both production code and test helpers.

**Fix in production code:**
```python
db = sqlite3.connect(db_file)
try:
    if not fts5_available(db):
        raise SystemError("FTS5 needs to be available")
finally:
    db.close()
```

### 3. `extract_meta_refresh` regex is fragile and enables open redirect
**Severity: MEDIUM**  
**Location:** `app.py`, `extract_meta_refresh()`

The regex does not validate the extracted URL. If a stored page contains `<meta http-equiv="refresh" content="0; url=https://evil.example.com/">`, `meta_refresh_url` is passed straight to the template and could be rendered as a clickable/navigable link to an arbitrary external domain. The regex also fails on `url=` without a semicolon (`content="0;url=..."` with no space) and misses unquoted `http-equiv` followed by whitespace-only attributes.

**Fix:** After extracting, validate the URL is relative or belongs to the same origin; reject absolute external URLs, or at minimum document the trust boundary explicitly.

### 4. Double HTML parse in `html_to_text_and_links`
**Severity: LOW-MEDIUM**  
**Location:** `crawl.py`, `html_to_text_and_links()` → `remove_nav_content()`

`remove_nav_content` parses HTML with BeautifulSoup, serializes back to string, then `html_to_text_and_links` immediately parses the result again. Two full parse-serialize-parse cycles per page. The serialization round-trip can also silently alter self-closing tags, encoding, and attribute order, making the output subtly different from the input.

**Fix:** Pass the `soup` object into extraction logic rather than re-parsing, or fold `remove_nav_content` into `html_to_text_and_links`.

---

### 5. `_search_executor` never shut down
**Severity: LOW**  
**Location:** `app.py`, module level

`_search_executor = ThreadPoolExecutor(max_workers=4)` is created at import time with no shutdown hook. Under repeated test runs or Gunicorn worker recycling, threads accumulate. CPython will GC it eventually, but it suppresses clean shutdown.

**Fix:** Register `atexit.register(_search_executor.shutdown, wait=False)` or shut down in a Flask `teardown_appcontext`-equivalent.

---

### 6. `count_crawled_urls_by_domain` uses SQL string surgery instead of urlparse
**Severity: LOW**  
**Location:** `app.py`, `count_crawled_urls_by_domain()`

The SQL CTE manually extracts origins via `instr`/`substr` on `://`. This breaks silently for IPv6 addresses (`http://[::1]/`), URLs with `userinfo@host`, and any URL where `instr(url, '://')` returns 0. Since all stored URLs pass through `normalize_url` (which validates scheme/host), the risk is low today, but the SQL is fragile if schema assumptions change.

**Fix:** Extract origins in Python after fetching rows, using `urllib.parse.urlparse`, or add a pre-computed `origin` column to the `pages` table.

---

### 7. `fts5_available` performs a DDL write on schema validation path
**Severity: LOW**  
**Location:** `utils.py`, `fts5_available()`

`fts5_available` creates and drops `__fts5test`. This is a DDL write executed during startup validation. On a read-only filesystem or WAL-mode database opened by another process, `CREATE VIRTUAL TABLE` can fail or leave a transient table if the `DROP` is never reached. The function is also called on every `ensure_database_present` invocation, not once.

**Fix:** Cache the result or use `SELECT fts5()` / a simpler FTS5 capability check that doesn't modify the schema.
